# WCAG 2.1 AA Mapping Matrix: Riverside Library Learning Portal

Ticket **MD-2026-0143**. 12 Success Criteria. Components are named as they appear in `/wireframes` and `/src`.

**Verification key:** **Auto-unit** means Vitest + Testing Library + `vitest-axe` (`npm test`). **Auto-browser** means axe-core in headless Chromium (`npm run audit:axe`). **LH** means Lighthouse. **Script** means `npm run contrast`. **Manual** means the screen reader and keyboard script in [`docs/manual-testing.md`](../docs/manual-testing.md).

| # | (a) Criterion ID & Name | Level | (b) Target Interface Component | (c) Technical Implementation Detail | (d) Verification Strategy |
|---|---|---|---|---|---|
| 1 | **1.3.1 Info and Relationships** | A | Page shell (all pages); `BookingForm`; resource cards | Landmarks: `<header>`, `<nav aria-label="Primary">`, `<main>`, `<aside>`, `<footer>`, plus `<section>`/`<article>` named with `aria-labelledby`. Heading levels run h1 to h3 with no skipped levels. Every input has `<label for>` / `htmlFor`. The time-slot radios and filter radios sit in a `<fieldset>` + `<legend>`. Resource metadata uses `<dl>`. | Auto-unit: `getByLabelText` for every field (`BookingForm.test.jsx`). Auto-browser: axe `landmark-*`, `heading-order`, `label`, `list` rules on all 10 page states. Manual: NVDA `D` and `H` quick-nav, `Insert+F7` landmark list. |
| 2 | **1.4.3 Contrast (Minimum)** | AA | Colour tokens in `wireframes/main.css` (greyscale wireframes + annotation colours) and `src/styles.css` (React app) | Palette chosen by calculation. Ink `#1B2420` on white is 15.91:1. All five topic "spine" colours carry white text at 6.07:1 or more, and their text-on-tint pairs (topic tags) are 5.41:1 or more. Marigold `#F5B700` fails on white (1.80:1), so it only ever sits behind dark ink (8.83:1) or on the dark green header (5.43:1). Wireframe content is greyscale (lowest text pair `#4B5A53` on `#EEF0EF`, 6.36:1). Both stylesheets list every computed ratio in their header comment. | Script: `scripts/contrast.mjs` checks every pair from both stylesheets and exits 1 below threshold (runs in CI). Auto-browser: axe `color-contrast` in real Chromium, 0 violations. LH: 100 on all four views. |
| 3 | **1.4.11 Non-text Contrast** | AA | Focus indicators, input borders, filter chips, error borders | Input borders are `#4B5A53` (7.28:1). The focus ring is a 3px ink outline (15.91:1) with a marigold halo, so it's visible on white, tinted panels and coloured chips. In the header the ring is marigold on green (5.43:1). Chip borders use the topic colour (6.07:1 or more). Error borders are `#B42318`, 3px (6.57:1). | Script: pairs flagged "non-text" with a 3:1 threshold. Manual: visual check at 200% zoom. |
| 4 | **1.4.1 Use of Color** | A | Topic colours, filter chips, form errors, slot availability, current page | Topic colours are always paired with the topic name as a text tag. A pressed chip gets a fill plus a ✓ glyph, plus `aria-pressed`. An error gets a ⚠ prefix, the word "Error:" for screen readers, a thicker border and a left marker bar. A booked slot is `disabled`, struck through, and labelled "(booked)". The current nav item has a marigold bar plus `aria-current`. | Manual: Chrome DevTools "Emulate achromatopsia" plus a greyscale screenshot review. |
| 5 | **2.1.1 Keyboard** | A | `FilterGroup`, `ToggleButton`, `Dialog`, all form controls | Only native interactive elements are used (`<button>`, `<a href>`, `<input>`, `<select>`, `<dialog>`). There are no `div` click handlers, so buttons, chips, accordion headers and radios respond to both Space and Enter natively. Links activate with Enter only, which is native browser behaviour and what the ARIA Authoring Practices specify. Space scrolls the page, and screen reader users expect that. | Auto-unit: `Catalogue.test.jsx` toggles the accordion with `{Enter}` and `' '`. `Keyboard.test.jsx` opens the dialog with Enter. Auto-browser: recorded Tab sequence per view (`docs/audit/axe-report.json`). Manual: full mouse-free run. |
| 6 | **2.1.2 No Keyboard Trap** | A | `Dialog` (registration confirm) | Native `showModal()` makes the page inert without a hand-written Tab trap. Escape always closes it. The `close` listener is attached once (see README trade-off 2). Collapsed filter panels use `hidden`, so they hold no invisible focus stops. | Auto-unit: Escape closes the dialog and focus returns to the trigger. Collapsed panels are skipped in Tab order. Auto-browser: Tab inside the open dialog stays in the dialog or moves to the browser UI and never to the page behind; Escape returns focus to "Register". |
| 7 | **2.4.1 Bypass Blocks** | A | `App` skip link; wireframe skip links | "Skip to main content" is the first Tab stop and becomes visible on focus. In the React version it calls `main.focus()`, so it doesn't change the hash route. `search.html` adds "Skip to results". | Auto-unit: the first Tab lands on the skip link, and Enter focuses `<main>`. |
| 8 | **2.4.3 Focus Order** | A | `PageHeading`, `BookRoom`, `Catalogue` | DOM order matches visual order (filters, then results; form, then sidebar). After a view switch, focus moves to the new `<h1>`. After a successful booking it moves to the "Booking confirmed" heading. After "Clear all filters" it moves to the Results heading. After a dialog confirm it moves to the success message, because the trigger has been removed. | Auto-unit: `Keyboard.test.jsx` (heading focus on route change, header tab order, focus after confirm). `Catalogue.test.jsx` (focus after clear). |
| 9 | **2.4.7 Focus Visible** | AA | Global CSS | Controls get `outline: 3px solid` ink with an 8px marigold `box-shadow` halo. Links get a "highlighter": a marigold background under ink text. That rule uses `!important`, because component link colours (header, error summary) otherwise overrode it and produced white or red text on marigold. Date inputs get `:focus-within`. There's a `forced-colors` override. | Auto-browser: every recorded Tab stop on all 6 pages is checked for a 2px+ outline AND for 4.5:1 text contrast *while focused*. That second check caught the override bug, which axe misses because it only tests the resting state. Manual: Windows High Contrast mode. |
| 10 | **3.3.1 Error Identification** | A | `BookingForm`, `ErrorSummary` | On blur, a field with an error gets `aria-invalid="true"`, and its error `<span>` id is appended to `aria-describedby` (after the hint). On submit, an error summary lists every problem as a link and receives focus. | Auto-unit: `aria-invalid` and the accessible description are asserted, plus summary focus and the summary link moving focus to its field. Auto-browser: axe on the error state. |
| 11 | **3.3.2 Labels or Instructions** | A | `BookingForm`, catalogue search | Visible labels on every field. Format hints ("YYYY-MM-DD", "Bookings open up to 14 days ahead") are linked with `aria-describedby`. The people hint updates with the chosen room's capacity. Optional fields are marked "(optional)". | Auto-unit: `toHaveAccessibleDescription` on email and date. Manual: NVDA reads label, role, then hint on focus. |
| 12 | **4.1.3 Status Messages** | AA | `AnnouncerProvider`, `Catalogue`, `BookingForm` | One permanent `aria-live="polite"` region and one `aria-live="assertive"` region. Result counts are announced politely, debounced by 600 ms. Field errors on blur, slot availability ("2 of 3 time slots available…") and booking confirmation are announced politely. While availability loads, the slot `<fieldset>` has `aria-busy="true"`. | Auto-unit: the live-region text is asserted for count, no-results, field error, availability and confirmation, plus a negative test that no announcement fires mid-typing. Manual: NVDA speech viewer log. |

Also addressed but not mapped in detail: **2.4.2 Page Titled** (the title updates per view), **2.4.4 Link Purpose** (visually hidden link suffixes), **1.4.10 Reflow** (single column below 52rem; no horizontal scroll at 320px on any page, checked in Chromium), **1.4.4 Resize Text** (rem units, `html { font-size: 100% }`), **readability** (body set in Atkinson Hyperlegible, a typeface designed by the Braille Institute for low-vision readers), **2.5.5-style 44px targets** (AAA, applied anyway), **4.1.2 Name, Role, Value** (`aria-expanded`, `aria-pressed`, `aria-controls`).
